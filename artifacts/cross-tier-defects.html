Reduced-API Defect Shift

With the perception-level APIs (S3, S4), every failed program from the 21-model ladder was repaired, verified, and tagged with the same defect taxonomy as S1. The tiers differ in two defect families, and the larger models lose most of the advantage they have at S1.

169/169 S3/S4 programs · 70 S1 programs · hand tags on both sides · repo commit 010a3e2

Findings

4% → 47%FRAME, S1 → S3/S4

About half of reduced-API programs get coordinate frames wrong: camera values used as world, wxyz/xyzw mix-ups, a 4×4 applied to a 3-vector. At S1 the API returns world poses and this almost never happens. Holds on all four tasks and with unverified records removed (48%). Fisher p ≈ 1e-11.

26% → 60%INTERFACE, S1 → S3/S4

Reduced-API programs misread what calls return and take far more often: plan_grasp given a two-object label map, masks unpacked from the wrong key, prompts that segment the wrong region. Holds on every task (verified only: 52%). p ≈ 3e-6.

1.54 → 3.3defects per program, ≥12B

At S1, defects per failed program fall with scale, from 4.17 (≤2B) to 1.54 (≥12B). At S3/S4 they sit between 3.2 and 4.6 in every size band. The large models' failed programs carry about twice the S1 count (verified only: 3.03). Mann-Whitney p = 0.0002.

94% = 95%SEMANTIC: no difference

Retracted: an earlier version reported SEMANTIC rising from 61% to 94%. That gap came from comparing an automated S1 tagger with hand tags. Hand-tagged on both sides, S1 is already at 94%.

How the programs were judged

Each failed program got a minimal repair: keep the model's code and fix only what is broken. The repair is verified in simulation. Tags name one cause per distinct fix, in the S1 taxonomy.

The bar

A repair is accepted when no scene fails in all k draws. k is measured per task as the smallest number of draws at which the reference program is rejected at most 5% of the time:

  • spill_wipe 1 (deterministic)
  • cube_lifting 5
  • cube_stack 12 when the program segments by point prompt (reference v7pg, 66.9%), and 16 by text prompt (v7pg_text, 60.2%, which loses scene 28 in 73% of draws).
  • nut_assembly 8

Coverage

  • 114 verified minimal repairs and 2 programs that pass as written.
  • 36 nut programs tagged against a shared reference. The reference fails 2 scenes, so these are not accepted.
  • 2 repairs rejected on the bar: one scene failed in every draw, with no model-attributable cause.
  • 15 programs that end mid-token, tagged syntax only.

Not counted as defects

Workarounds for the environment are recorded per program but never counted as tags:

  • subtracting the green cube's pixels from the grasp mask;
  • one fixed IK solve to reset the solver's seed, which otherwise carries over between trials;
  • shared wipe and placement kits.

Checked on the way

  • Tagger confound: on the same 70 S1 programs, hand tagging finds 2.77 tags per program and the automated tagger 2.06. All S1 programs were re-tagged by hand, and every number here compares hand with hand. Both S1 counts are reported: the scale gradient is 4.17 → 1.54 by hand and 3.21 → 1.15 automated.
  • Token cap: raised from 2048 to 8192 tokens. qwen3vl-8b's truncation is a repetition loop at any cap. gemma3-12b completes at 2,132 tokens and still crashes at line 27. Of 50 truncated programs, 35 already have other diagnosed defects. qwen3vl-32b, the last large-model candidate, also loops at 8192 tokens. The cap explains no ≥12B failure.
  • Privileged state: the observation exposes object poses. A scan of all 5,040 S3/S4 episodes found no program reading them.
  • nut_assembly scenes 14 and 21: a grasp 5 mm closer to the ring fixes scene 21 (reference v8, 87/90). Scene 14 fails on an IK solution at a joint limit that the program cannot steer around.

Limits

  • One rater tagged both sides. In a same-rater blind re-tag of 60 programs, agreement is κ 0.89 overall. It is lowest for FRAME (0.67), and the re-tag found fewer causes per S3/S4 program (2.93 against 3.43 filed), so the defect-count gap is the least robust finding. A second human rater has not been run yet; the packet is in artifacts/second_rater/.
  • The nut S3/S4 records rest on a reference that fails 1 of 30 scenes (v8, 87/90). They are excluded in the verified-only figures, and the findings hold.
  • These are failed programs only. Defect counts describe what goes wrong when a program fails, not how often programs fail.
